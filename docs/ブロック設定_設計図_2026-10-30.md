## 0. 決まったこと / 決めてほしいこと

**決まったこと**
- 時計は **ふつうの 12 時間の時計 × 3** — 🌅 朝 5時〜12時 (5 の位置から上まで) / ☀️ 昼〜夜 12時〜翌0時 (1 周) / 🌙 深夜 翌0時〜翌5時 (上から 5 の位置まで)。使わない位置は薄い輪。12 時・翌0 時をまたぐブロックは両方に同じ色。
- ブロックの文字は **並び順で自動 (A・B・C…)**。
- 設定できるのは **ふるり (👑 マスター) だけ** — 画面の出し分け (`data-master-only`) で。**DB では縛らない** (RPC は今までどおり anon が実行できる・名乗りは自己申告なので DB に判定を足しても縛りにはならない。運営担当の役割と同じ「誤操作防止」の扱い = CLAUDE.md の決めごと)。

## 1. 画面

### 1.1 置き場所 (Q1)

- 運営タブ › **👑 マスター** (ふるりだけに出るタブ) › シーズン制御 の下に **「🧱 ブロックの設定」** のカード。
  `js/domain/opsLayout.js` の `CARDS` に 1 行 (`id: 'opsSecBlocks'`, `tab: 'master'`, `span: 12`, `opsOnly: true`)。カード本体は `data-master-only` (役割で出す・🛠 の ON/OFF に関係なく)。
- シーズンが無いときは「シーズンを作ってから」の 1 行だけ。**流れ**: シーズン作成 (既定の 6 つで作る) → 🧱 ブロックの設定で直す → Discord でメンバーに「出られるブロック (A/B/…) と凸数」を聞く → 👥 › ⏰ で登録 → 🧱 組む。
- ✏️ シーズン編集 (`#opsSeasonEditModal`) からは **ブロックの行 (`#opsSeasonEditBlockRows`・足す・既定に戻す) を外す**。ハード日・ボス・メンバーの入力のスイッチは残す。

### 1.2 カードの中身 (モックどおり)

1. **時計 3 つ** (インライン SVG・色はトークン `--blk-0`〜`--blk-11` を `:root` の両テーマに足す)。色の帯を押すとそのブロックを選ぶ (行が光る・真ん中に「A 5〜9時 · 4 時間」)。ドラッグで区切りを動かす操作は**作らない** (スマホで細かい操作は危ない。行の select で足りる)。
2. **ブロックの行**: 文字のバッジ (並び順) / 名前 (任意・6 文字・Q2) / 「5時 〜 [9時 ▾]」(終わりの時刻の select = 次の始まりが連動。最初は 5 時・最後は翌5時で固定) / 「分ける」(2 つに) / 「✕ 消す」(前のブロックに合わせる)。
3. **一括**: 4 つ (6 時間) / 6 つ (4 時間) / 8 つ (3 時間) / 12 つ (2 時間) / いまの既定 (朝・午前…)。
4. **保存**: いまの `supabaseUpdateSeasonBlocks` (入口で `normalize` → RPC `ops_set_season_blocks` (50) → 50 未適用は読んで混ぜて書く) をそのまま使う。保存のあとは `seasonStore.invalidate()` + `opsStore.invalidate()` (いまの ✏️ と同じ)。
5. **変えられないとき (Q5)**: 行は読み取り専用・時計はそのまま・保存の代わりに理由の文「参加可能時間の凸数 N 件・予約 N 件・決定 N 件がもうあるので、このシーズンのブロックは変えられません。変えるならシーズンを作り直してください」(ボタンの監査 ③: 押せないボタンを置かない)。
6. 「メンバー・運営にはこう見える」の見本は**本番には置かない** (モックだけ)。

### 1.3 文字がどこに出るか (A・B・C…)

`raidBlocksDomain.labelOf` を通る場所はすべて自動で「A 5〜9時」になる。読む側は **ブロックの添字** を渡す (下 2.1)。

| 場所 | いま | これから |
|---|---|---|
| 👥 › ⏰ 参加可能時間のシート (チップ) | 「朝 5〜8時」 | 「A 5〜9時」/「A 朝 5〜9時」 |
| ホームの ⏰ カード (見るだけ) | 帯の下の名前 | 文字 (+ 名前) |
| 👥 メンバー状況の凸数 | 「凸数 朝 1 · 夕方 2」 | 「凸数 A 1 · D 2」 |
| 🧱 組む のブロックのボタン・盤・手順の帯・条件のスタンプ | 名前 | 文字 (+ 名前) |
| ✅ 決定 → 📅 レイド予定表・きょうの凸・⚔️ ✓ 凸の記録 | 名前 | 文字 (+ 名前) |
| 決定の通知「🧱 夕方 17〜20時 のあなたの凸が決まりました」 | 名前 | 「🧱 D 17〜21時 の…」 |
| 📸 模擬の取り込みの 〆 / 凸の予約の「どのブロックで」 | 名前 | 文字 (+ 名前) |
| ヘルプ・ツアー・Discord 用の文面・練習の案内 | 「朝」「夜」 | 文字で言い直す (練習は 5 節) |

## 2. データと判定

### 2.1 ドメイン (`js/domain/raidBlocks.js`) — 変えるのはここだけで、読む側は追随

- **保存の形は変えない**: `seasons.metadata.blocks = [{ name, from, to }]` (from / to = 含む時・5 時始まりの並び)。**文字は保存しない** (並び順から `letterOf(i)` = `'ABCDEFGHIJKL'[i]`)。SQL の追加は無い (Q5 のガードを DB にも置くなら SQL 58・下 4)。
- `normalize`: **名前は任意** (空でよい・6 文字まで・**同じ名前の検査は名前のあるものだけ** = 空は何個あってもよい・Q2)。`out[i]` に `letter` と `label` を持たせる。
- `normalize` の出力に **5 つの欄** (言い方 4 つ + 名前) を持たせ、読む側は自分で文を組まない:
  - `letter` = 「A」/ `name` = 「朝」か空 / `short` = 「A 朝」(名前が無ければ「A」) / `range` = 「5〜9時」/ `label` = 「A 朝 5〜9時」(= `short` + `range`)。
  - `labelOf(b, i)` = `label`。**終わりは時刻で言う** (`range` の `end` = to の次の時・翌4 の次は「翌5」) (Q3)。1 時間のブロックも「9〜10時」。
- `countsLabel` (凸数の「朝 1 · 夕方 2」)・`blockStates` の名前・`blocksOfSeason` の `label` も同じ関数から。
- **鍵は変えない**: 凸数 `countKey` = `${from}-${to}` / 決定 `publishedPlansDomain.keyOfBlock` = `from-to` / 予約 `block_from` / `block_to` / 配信の `blockScope`。文字は見せ方だけなので、ブロックを**足し引きしなければ**既存の鍵はそのまま合う。

### 2.2 読む側 — 5 つの欄を写して、自分で文を組まない

- **方針**: `normalize` が作る `letter` / `name` / `short` / `range` / `label` の 5 つを、ブロックを**写す所にも全部写す** (写しの対象: `decidePlan` の決定の控え `decided.blocks[]`・`timetable` の行・`todayRows` の行 / `blockScope` / `raidBlocks` の `blockStates` / `todayRows` / `countsLabel` / `blocksLabel` の出力 / `mockIntake` の 〆 `deadline` / 予約の申請の控え `_resvReq.block` / `reservations` が読む `blockScope`)。読む側はその中の `short` (言葉として) / `range` (時刻として) / `label` (両方) を読み、**`name` から自分で文を組まない**。古い控え (`short` が無い決定・配信) は `short || name || letter` で読む。
- **置き換える所**: 網羅は**実装の ① で grep の一覧を作って全部を置き換え、見張りのテストで固定する** (下)。2026-10-30 の main で数えた主なもの (行番号は実装時にずれる):
  - **崩れる 4 か所** = `b.label.slice(b.name.length)` のように「label は name で始まる」前提: `index.html` 10176 (📅 きょうの凸の行)・14696 / 14712 (⏰ 参加可能時間のシートのチップ)・24161 (運営発の予約シートのブロック選択) → `range` と `short` を読む。
  - **`blk.name` / `block.name` / `blockScope.name` / 控えの `name` をブロックの言葉に使う所**: `index.html` 約 30 行 (ホームの決定の文 7988 / 7990・配信カードの `blockScope` 10043 / 10182・ブロックのチップ 10513・予約シートのチップ 10955 と控え 10924・📸 の 〆 18855・🧱 組む のボタン 23103 / 23107・見出し 23171 (+ 独自の `_obHours` → `range`)・決定の文 23157 / 23166 / 23249・📌 のログとトースト 23422 / 23427・組む / やり直す 23479〜23511・一気に組む 25391〜25517 など) → `short` (古い控えは `short || name || letter`)。
  - **ドメイン**: `raidBlocks.js` 222 (`blockStates`)・233 (`blocksLabel` = ⏰ 帯の「朝・夜 (一部)」)・280 (`todayRows`)・334 (`countsLabel` = 「朝 1 · 夕方 2」) / `decidePlan.js` 139・224・274 (決定の控えと時間割の `name`) / `mockIntake.js` 56・142 (〆 の `name`) / `reservations.js` 690 (`blockScope.name`) → 写すときに `short` / `range` も入れ、文にするときは `short`。
  - **`blk.label` をそのまま渡す所はそのまま** (`label` が文字つきになる): 算出の `availableAtLabel`・`blockScope.label`・承認の影響の注記・手順の帯・ブロックの配信の通知・一気に組むの `conditions.block`。
  - `resultIntake` / `planBoard` / `memberStatus` の `.name` はボス・人の名前 (対象外)。
- **見張り (テスト)**: `index.html` と `js/domain` に `label.slice(` が 0 件・ブロックの `.name` を文字列の連結やテンプレートに直接入れる行が 0 件 (grep の正規表現で数える・名前を出したい所は `short`)・`decided.blocks[]` / `blockScope` / `_resvReq.block` / `deadline` を作る所が 5 つの欄を写している・`countsLabel` / `blocksLabel` / `blockStates` / `todayRows` の出力が `short` を使う、を文字列と実行の両方で固定する。
- 決定の JSON (`decided.blocks[]`) は**決めた時点の文字**で保存される (古い決定には `short` が無い → 読むときは `short || name || letter` で落ちない)。Q5 で決定のあとはブロックを変えられないので、文字がずれることは無い。

## 3. 参加可能時間のリセット (Q4)

- **事実**: `availability` 表 (player_id, time_slot) は**シーズンをまたいで残る** (消す処理が無い)。盤面ローダは確認の有無に関係なくこれを読むので、確認していない人の古い時間も組む計算に入る。今期ぶんとして新しいのは `availability_confirmations` (いつ確認したか・今回は難しい・凸数) だけ。
- **作り**: シーズン作成シート (`#opsSeasonCreateModal`) に「全員の参加可能時間を空にする」のスイッチ (`#opsSeasonResetAvail`・既定 ON・🧪 テストに印を付けたら隠して OFF)。`supabaseCreateSeason` が **本番のとき**、`availability` を全削除 (`delete().gte('player_id', 0)`)。確認のダイアログに「参加可能時間 N 人ぶんを空にします」を足し、活動ログに「シーズン作成で参加可能時間を全員ぶん空にした (N 人)」。
- **順序と失敗 (1 つのトランザクションにはしない・作成そのものが seasons → bosses → 模擬のクリア の複数リクエスト)**: 動いているシーズンの確かめ → 同じ月キーの確かめ → **参加可能時間の削除 → シーズンの作成** の順。削除が失敗したら**作らない** (「何も変えていません」で止める = 新しいシーズンだけできて古い時間が残る、を作らない)。削除のあとで作成が失敗したら、時間は空のまま (どのみち新しいシーズンのために空にするものなので、そのまま作り直す。知らせの文に「参加可能時間はもう空にしてあります」)。模擬のクリアは今までどおり作成のあと (失敗は console.warn の既存の扱い)。
- **テストシーズンでは消さない**: テストの終了は模擬 (`damages_snapshot`) しか戻さない。時間を消すと戻らない。
- **消したあとの見え方**: ホームの ⏰ カード = 「未登録」(本人には「Discord で運営へ」の案内のまま) / 👥 メンバー状況 = 時間未登録の札 (候補にしない) / ソルバーは `excludeTimeUnknown` で未登録の人を組まない (段階 2b のまま)。= 9a の流れ (Discord の報告 → 運営が ⏰ で登録) と同じ。
- 消さないもの: 得意属性・SLv・通知の購読・`notify_all_hours`・今期の確認 (37 は季節ごとなので新しいシーズンでは最初から空)。

## 4. 変えられる期間 (Q5) と DB のガード

- **なぜ**: ブロックを足す・消すと文字がずれ (B の前に 1 つ入れると C→D)、鍵 (`from-to`) が合わなくなる — 凸数は `normalizeCounts` が黙って落とす・決定の `appliesTo` が外れる・ブロックの予約の窓が古いまま。メンバーに「C に出られる」と言ってもらったあとに C の意味が変わる。
- **画面**: カードを描くとき、そのシーズンの `availability_confirmations` (block_counts あり)・`plan_reservations` (time_mode = 'block'・生きている状態)・`published_plans` (decided) の件数を数え、1 件でもあれば読み取り専用 (1.2 の 5)。
- **DB**: RPC `ops_set_season_blocks` (50) に同じ判定を足す (**SQL 58**: 件数が 1 以上なら RAISE)。画面だけだと、古い版・2 人の運営の競合で通る。PGlite で 01〜58 を流して確かめる (scratchpad の `apply-all.mjs` の型)。50 未適用の「読んで混ぜて書く」の道は、58 未適用でも動く (ガード無しで通るだけ)。
- 「既定に戻す」も同じ条件。

## 7. 据え置き・やらないこと

- 時計をドラッグして区切る操作 (1.2)。
- 途中でブロックを変えたときの凸数・予約・決定の自動付け替え (Q5 でロックする)。
- 権限: マスターだけは画面の出し分け (`data-master-only`) だけ。RPC (50 / 58) に判定を足さない (RLS は anon 全許可・名乗りは自己申告 = 足しても縛りにならない。今までの役割と同じ誤操作防止)。
- シーズン作成シートでブロックも一緒に決める (作成は既定 6 つのまま → カードで直す)。
