問題なし (こちらの裏取りつき):
- **吸収モード × ブロック**: ブロックで絞ると「踏破できないレベル」に落ちやすいが、撃破狙いのままにしても与ダメ・残り凸は ±0.1% (`tests/bench-blockflow/frontier-kill.mjs`・×1 / ×1.15 / ×1.3)。直さない
- 凸数の上限 (applyPick / undoPick / assignLv4 / restoreSnapshot の対称性) / 予約の置き方 (黙って消える経路なし) / 時間厳守の修復 (60 回で止まる) / Lv4 の検知 / 出力の整合 / 決定性と性能

ブロック制で運営が知っておくこと (Codex のまとめ):
- ブロック予約は「その時間帯のどこか」の約束。窓の中に本人の登録時刻が無い古いデータでは窓の先頭に置かれる
- 時間未登録の人はブロックの対象には見えるが候補には使われず、予約だけは優先される
- ブロックの中で Lv を削り切れないときは、次の Lv を仮定せず残 HP に無駄なく入れる配り方になる (撃破を狙わないように見えるが結果は同じ)
