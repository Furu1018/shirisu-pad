## 1. 新しい運営の流れ (3 画面)

### ① 模擬ダメージ表

- 入力は **名前・属性・ダメージ** の 3 つ (提出してもらったものを運営が打つ)。📸 スクショの読み取りは**任意** (読ませると 5 キャラも入る)。
- 一覧は **人 × 5 属性** の表。マスにダメージ (B) と編成の番号。同じ人の 2 つの編成に同じキャラがいれば**赤い枠** (被り = 1 日に両方は使えない)。
- 届いていない人は空のマス。表の上に「そろった人 N / M」。

### ② 凸時間帯配分表

- 表は **ボス (行) × ブロック 5 時から 4 時間ずつ (列)**。行の頭に ボス名・弱点 PT・**あと ◯B** (Lv1 の残り HP)。
- 右 (スマホは下) に**模擬のピース** (名前・属性・ダメージ)。
- **手動**: ピースを表のマスへ**ドラッグ & ドロップ** (スマホは ピースを押す → マスを押す)。置けるのは「その人が出られるブロック」×「ピースの属性が弱点のボス」だけ。置いたピースは模擬表でグレーに。**被りの相方もグレー**。
- 行の HP が 0 になったら「撃破 ✓」で**その行は止まる**。5 体とも撃破したら **Lv2 の 5 行**が下に出る (Lv3 も同じ。Lv4 はボス 5 だけ・無限)。
- **自動**: 「自動で組む」= いまの最適凸プラン算出。手で置いた駒は動かさない (手で置く → 自動で埋める → 手で直す、の順でもよい)。

### ③ 凸プラン決定

- 「**決定**」を押すと 1 日ぶんがそのまま配信され、メンバーの PAD に出る。決定し直せば上書き (変わった人には通知・9h のまま)。
- メンバーが見る形は **時間割 1 つ** (ブロックごとに「B1 オベリスク — あるる 鉄甲PT 28.4B …」・自分の凸は強調・✅ 確認しました)。配信カードのタブ (わたしの凸 / 全体 / 時間割 / 盤)・📅 きょうの凸 は時間割に統合する。

## 6. 10/26 夜・ふるりの追加の構想 (質問への回答より先に伝えられたもの)

> 全体の進行として、そのブロックでレベル 1 が終了するかどうかをみていく。朝ブロックでレベル 1 が完了した場合、その朝ブロックではレベル 2 は行わず次のブロックからレベル 2 をスタートさせる。
> 運営の動きは、メンバーの模擬の登録と、プランを組むこと。本番の凸報告は実際の数字や構成は入れずに「凸が完了したことだけ」を PAD に報告。大きくダメージがずれていないかは、30 分から 1 時間おきに BlaBlaLINK の画像で進行度を照らし合わせる。
> 凸プランをいかに組みやすくするかが今回のポイント。「ブロックを組む」だけでなく「何時から何時のブロックを組む」というボタンにする。ボタンはある程度大きく、中の組まれている様子が把握できるとなお良い。
> その時間帯のボタンを押すと「その時間帯に凸できるメンバーの模擬の一覧のみ」が見れる。その時間帯以外も凸が可能なメンバーはそれはそれで分かるように (融通が効かないメンバーをそのブロックに積極的に配置しなければならないことが分かる)。
> 組んでいく際は、視覚的にボスの HP がどのくらいその人の凸で削れるか分かるように。運営がある程度手動で組む → 最適凸プランで自動で組む、の流れで「予約」にあたる部分をカバーする。

### 読み取り (設計に落としたもの)

| 項目 | 決めごと | いまの PAD との関係 |
|---|---|---|
| レベルの進み | **レベルはブロックの頭でしか変わらない**。朝で Lv1 を撃破したら朝の残りは使わず、Lv2 は午前から。終わらなければ午前も Lv1 の続き (残り HP を持ち越す) | ソルバーに「レベルの切り替えはブロックの境だけ」の規則を足す (S3)。手動の盤はそのブロックで挑む Lv の 5 行だけを出す |
| 運営の仕事 | 模擬の登録 (S1) と プランを組む (S2〜S3) だけ | 催促・予約・承認・結果の取り込み (OCR) は外す |
| 凸の報告 | **「凸が完了した」だけ** (数字も編成も入れない)。読み: メンバーが自分の時間割の行で ✓ を 1 タップ (運営が代わりに付けてもよい) | 📥 結果の取り込みの OCR は使わない。✓ は `attacks` の行 (ダメージ 0・編成 = 配信の編成) か、配信の確認と同じ軽い記録にする (実装時に決める) |
| HP の照合 | **30 分〜1 時間おき**に BlaBlaLINK の画像で 5 体の HP を読む | 🎯 ボス HP 更新 (9e) をそのまま。鮮度の印を「30 分」で出す |
| 組む画面 | **「朝 5〜8時 を組む」の大きなボタン × 6**。中に Lv・置いた凸・ボスごとの残り (小さな棒) | 条件パネルのブロックの選択を置き換える |
| 押したあと | **その時間帯に出られる人の模擬だけ**を並べる。🔒 = この時間帯しか出られない人 (先に置く)。ほかの時間帯にも出られる人は、その時間帯を薄い字で | 🧩 模擬ピースの箱を「出られる人だけ + 融通の印」に |
| 置く | ボスの行に置く (時刻は決めない・ブロックの中は算出が決める)。**幅 = ダメージ** で残り HP が減るのが見える | 🧱 盤の幅 = ダメージ をそのまま。置いた駒は 📌 (ブロックの仮置き) として算出を拘束 |
| 自動 | 手で置いたあと「残りを自動で組む」= いまの算出。手で置いた駒は動かさない | これが予約の代わり |
| 決定 | 組めたブロックまでを決定 (配信)。先のブロックは埋まり次第、決定し直す | ブロック別配信・一気に組む を置き換える |

モック ② を この形に作り直した (ブロックのボタン × 6 / 押すと出られる人の模擬と 🔒 / ボスの行に置くと幅 = ダメージで残りが減る / 5 体撃破で次のブロックが次の Lv / 決定は組めたところまで / 時間割に「✓ 凸しました」)。

## 7. 実装の設計 (2026-10-27・Opus で着手)

### 済み
- **S3 の規則 (先に入れた)**: ソルバーの入力 `levelStartsAtBlock` (ブロックの頭の添字)。ブロック k で踏破したら次のレベルは k+1 の頭から・最後のブロックで踏破したら次のレベルも Lv4 も開かない・B5 の予約の Lv4 の読み替えも次のブロックの頭から。**渡さなければ出力は 1 バイトも変わらない** (指紋 120 盤面)。画面は算出と承認の影響の 2 か所で常に渡す。`planChain.projectBoard` に `levelLockInBlock` (踏破したブロックの残りの凸は実行しない)
- **S2 凸プランを組む**: `js/domain/blockBuild.js` (overview / pinsPlan / trayPieces / canDrop) + 🧱 組む のカードの頭 (`renderOpsBuild` ほか `_ob*`)。手で置く = 📌 ブロックの仮置き (DB・別の端末でも見える)。自動 = そのブロックの始まりの盤面 (前のブロックを模擬どおり削れたと仮定) から、手で置いた駒は動かさず。自動の結果は決定するまでこの端末だけ。従来の条件パネル・算出・配信は畳んで残す

### S4 の設計 (決定 → メンバーの時間割 → ✓ 凸しました)
- **決定 = 配信の行を 1 行** (`published_plans`・blockScope 無し)。`plan.decided = { upTo, blocks: [{ key, idx, name, label, from, to, level }], at }`。組めたブロック (いまのブロック〜最後に組んだブロック・途中に組んでいないブロックがあれば止める) の自動の結果をブロックの範囲で切って 1 つにまとめる。
  時間の過ぎたブロックと、今回組み直していない決定済みのブロックは、前の決定の行からそのまま写す (決定し直しで前のブロックの割当を消さない)。端末を開き直したら、前の決定の行から各ブロックを読み戻す (自動の結果として)
- 決定の直前に照合: シーズン・手で置いた駒の指紋・前の決定の行の id (組んだあとに別の運営が決定していたら止める)
- **通知**: 人ごとに 1 通。初めてのブロックの割当は「🧱 あなたの凸が決まりました」、前の決定から変わった人は「🔄 あなたの凸が変わりました」(9h と同じく ✅ を押していたかで文を分ける)、外れた人にも。変わらない人には送らない (二重送信よけは `raid_event_notices` の `decide|…`)
- **メンバー**: 時間割 1 つ (ブロックごとに Lv・ボス・名前・PT・編成。自分の行を強調)。決まっていないブロックは「まだ決まっていません」。✅ 確認しました は残す。`PLAN_SCHEMA` を 4 に (古い版は「更新してください」)
- **✓ 凸しました**: 自分の行に 1 タップ。数字も編成も入れない。記録は `attacks` に **ダメージ 0・予定の編成・予定のダメージは別の列** の行 (SQL 56: `source` 'tap' / 'ops_tap'・`planned_damage_raw`・`plan_key` (二重押しを止める一意索引)・RPC `mark_attack_done` = 採番と 3 凸の上限は report_attack と同じ・HP は動かさない)。
  残り凸と使ったキャラが正しく減るので、次のブロックを組むときに正しい。HP は運営が BlaBlaLINK の画像で直す (🎯)。分析のダメージの集計からは tap の行を外す。運営が代わりに付けることもできる。取り消しは 'tap' の行だけ消す (HP は戻さない)。
  ✓ を付けたら、その凸の 📌 (手で置いた駒) は外す (残り凸を二重に数えない)
- 未適用 (SQL 56) の間: ✓ ボタンは「SQL 56 を実行してください」と言って止まる。練習の偽サーバにも同じ列と RPC を足す

### 直すこと (敵対的レビューで確認済み 12 件・重い順)
1. **[高] 決定し直すと、いまのブロックで済んだ凸が決定から消える** — build が newIdxs のブロックを ov の実行される凸だけで作り直すため、✓ / 報告済みの凸が消え、本人に「変わりました / 外れました」が飛ぶ。

   `_BB_FILL[weakness]` は own プロパティで引く (`constructor` / `__proto__` で落ちる)
3. **[中] 決定の読み戻しの指紋が「読み戻した時点の駒」** — 決定後に置かれた 📌 を見落とす。決定の各ブロックに決定時の指紋 (ハッシュ) を `decided.blocks[].fp` で残し、読み戻しはそれを使う
4. **[中] ✓ で 📌 が released / 約束が fulfilled になると、指紋が全部変わって組んだ結果・読み戻しが全部「要組み直し」** — 指紋を作るとき release_reason 'fulfilled' の released → pinned、fulfilled → approved とみなす。盤の「実行されない駒」から済んだ凸を外す
5. **[中] 最新の行が決定でないとき (決定のあとに従来の配信)、範囲に絞った決定で時間割を描く** — currentDecided のときだけ時間割に。それ以外は plan から decided を外して従来の表示
6. **[中] 運営の代理 ✓ が「数字で報告済みの凸」を見落として 2 行目を作る** — 他人の行にも 人・レベル・ボスの数で消し込みを掛ける
7. **[中] 取り消しで駒が戻らない** (約束は fulfilled・📌 は released のまま) — 少なくとも「駒は戻りません (運営が置き直します)」と出す。戻すなら RPC で
8. [中・半数] 「外れました」のあと同じ割当で戻った人に通知が届かない — 通知の鍵は常に決定の id 入り (`decide|人|p<id>|sig`) に (notices は変わった人しか出さないので重複しない)
9. [中・半数] 通知の確保が 'held' / 一時エラーだと黙って捨てる — failed に数えて「N 人に送れませんでした」と出す
10. [低] 割当の無い人の ✅ が引き継がれない — 通知の対象でない、前の決定を ✅ した人を全員引き継ぐ
11. [低] 同じブロック・同じボスに 2 凸あると並び順だけで「変わりました」— rowsOf の並びの最後に sig で並べる
12. [低] `_myTappedKeys` が消えない — DB の行で確かめられた鍵は外す
