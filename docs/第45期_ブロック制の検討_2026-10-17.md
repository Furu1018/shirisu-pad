## 1. 旗振り役詰所 (10/13〜14・Enter95 / ねむねこ) で揃ったこと

**合意できている**
- メンバーの入力は最低限。模擬は Discord にスクショを貼るだけ (運営が確認してリアクション)
- PAD への入力は運営 (入力する人が増えるほど予期しないエラーが増える)
- 運営はピースを自由に置きたい。自動配置は参考案でいい (Enter95: 「誰と誰を組み合わせれば取り切れるかを自由に試せなかった」)
- 凸できる時間はアンケート。3時間くらいの区切りで十分。昼間は長めでもいい
- メンバー側は配信されたプランを見るだけ
- 一次情報が Discord に残るのは都合がいい

**まだ決まっていない**
- 時間のアンケートを PAD で持つか (ねむねこ: 枠を最適化すれば事故は少なそう / Enter95: PAD の機能では不安)
- 模擬の提出シートをメンバー画面に残すか消すか
- 凸報告を本人がするか、運営が BlaBlaLINK のスクショからまとめて入れるか

**PAD 以外**: 抜ける人が出て 20 人くらいから仕切り直す可能性。募集文に模擬提出と凸管理を明記して同じ目標の人を集める。
定期連絡とハード/ソロレイドの結果共有、止まっている人には改善相談、それでも動かなければやんわり追放。
運営目線で考えられる人があと数人欲しい。

## 2. ふるりの案: レイド日をブロックに分ける

朝 (5〜8時) / 午前 (9〜11時) / 昼 (12〜14時) / 午後 (15〜17時) / 夕方 (18〜20時) / 夜 (21〜23時) / 深夜 (0〜4時) の 7 つ。

- メンバーページの機能は最低限 (完全同意)。運営の負担も気にしている (全員ぶんの登録は大変では)
- ピースを自由に動かして模擬的な 1 日の計画を建てたい
- ただしメンバーの負担を考えると、完璧な模擬を前日の夜に用意するのは難しい
- **昼までに Lv1 を倒せる火力があればいい。Lv3 が夕方からなら、Lv3 で使いたい人の模擬は夕方まで待てる**
- 全体の最適解は出せないかもしれないが、「模擬を〇〇までに出す」メンバーの負担と「開始から完璧な計画」を求められる運営の負担を両方減らせる
- 第44回の一番の反省は「当日のプラン組み直しでメンバーを振り回した」こと。ブロック制なら後ろのブロックはまだ約束していないので、組み直しても誰の約束も壊れない (L1/L4/L5 で守ろうとしていたものを、約束の範囲を狭めることで構造的に守る)

## 3. 代償を測った (`tests/bench-block.mjs`)

**盤面**: 第44回の実データ (`data/2026-09.json`・30人・90凸・ボス5体)。各メンバーの模擬 = 実際に出した凸のダメージ
(締め凸 9 件は本人の非締め凸の最大で代用)。時間帯は実データに無いので、夜型・昼型・朝+夜・いつでも を混ぜて 60 通り振った。
時間厳守 ON (画面の既定)。実行は「計画の時刻に本当に出られなければ、その人が本当に出られる次の時刻に動く」「その時にボスが死んでいれば凸を失う」。

| 案 | 何をするか |
|---|---|
| A | 前日に全員の模擬がそろい、朝5時に **1日ぶんを1回** 組んでそのとおり実行 (今の使い方) |
| B | A と同じ情報で、ブロックの頭に組み直し・そのブロックぶんだけ実行 |
| C | B + 模擬は「自分が最初に出られるブロックの前」に届く |
| D | B + 模擬は「自分が出られるブロックのどれかの前」に届く = ぎりぎりに出す人 |
| E | B + 時間を **ブロック単位で申告** (1時間でも出られればそのブロックは○) |
| F | C + E |
| H | C + **そのブロックに出られる人だけ**で組む (ブロック制そのもの) |

**結果** (ゲームに入る与ダメ・60通りの平均)

| | 実データ ×1.0 (天井 3126B) | 実データ ×1.15 (天井 3595B) | Lv4 到達 (×1.15) |
|---|---|---|---|
| A 1日ぶん1回 | 2404B | 2693B | 1/60 |
| B ブロック・全情報 | 2459B (+2%) | 2773B (+3%) | 1/60 |
| C 模擬は自分のブロック前 | 2924B (+22%) | 3143B (+17%) | 44/60 |
| D ぎりぎりに出す | 2932B (+22%) | 3135B (+16%) | 40/60 |
| F ブロック単位で申告 | 2874B (+20%) | 3083B (+15%) | 20/60 |
| H ブロックの人だけで組む | 2925B (+22%) | 3143B (+17%) | 44/60 |

合成盤面 (`BOARD=synth`・既存ベンチの生成器・30人・5属性・前日の状態) でも同じ傾向 (A 1299B → H 1578B・+21%)。
実データ ×1.0 は 90 凸の合計 (2981B) が Lv1〜3 の総HP (3076B) に届かず、どう組んでも Lv3 を踏破できない盤面。×1.15 は Lv4 が開き得る盤面。

### 読み方

1. **ブロック制の代償は無い。むしろ 15〜20% 増える。** ただし「ブロック制が賢い」のではなく、**今のソルバーの弱点をブロック制が構造的に避けている**。
   盤面を 1 つ覗くと: Lv1 ボス1 の残り 22B を埋めるのに、12〜17時に出られる 3 人 (計 9 凸) を使わず、22時の人 (22B ぴったり) を選ぶ。
   オーバーキルの小ささを優先した結果 Lv1 の踏破が 22時まで遅れ、昼間の人 5 人 14 凸が「停止レベルの開放時刻以降に戦闘可能時間がない」でまるごと未使用になる。
   時間厳守 ON だと「早く踏破して多くの人を参加させる」価値がソルバーの点数に無い。A の未使用 15 凸 (30人の 1/6) はこれ。
   第44回は厳守 OFF だったので表に出なかった (OFF だと ⚠時間外 のベストエフォート凸が大量に出て、実行時に死んだボスへ当たる = 別の問題)。
   **第45回を厳守 ON でやるならブロック制を採らなくても直す必要がある。**
2. **模擬を遅く出しても損しない (C ≒ D)。** 自分のブロックの前に出せば十分
3. **時間をブロック単位で聞く代償は 1.5〜2% (F vs C: −50〜60B)。** 計測では「来たらボスが死んでいた人は凸を失う」と厳しく扱っていて、それが 1 日 8 凸。
   実際はその人が運営に聞いて別のボスを叩くので、失うダメージより運営の手間として出る
4. **一番効くのは「そのブロックに出られる人だけで組む」(H)。** C と同じ値で未使用もほぼ 0

### 計測の限界
- 時間帯の分布は想像。本物の第44回の時間帯が「ほぼ全員夜」なら A の未使用はもっと少ない
- 模擬は「実際に使った 3 凸」だけ。本当の模擬の品揃えはもっと広い
- 締め凸 9 件は代用

### 使い方
```sh
node tests/bench-block.mjs                      # 実データ・60通り・時間厳守 OFF
BENCH_N=60 STRICT=1 node tests/bench-block.mjs  # 時間厳守 ON (画面の既定) ← 上の表
SCALE=1.15 STRICT=1 node tests/bench-block.mjs  # ダメージ 1.15 倍 (Lv4 が開く盤面)
BOARD=synth STRICT=1 node tests/bench-block.mjs # 合成盤面
```
ソルバーを直したら A の「未使用」が減るかを同じ物差しで見る。

## 4. 提案 (PAD の改修)

ブロック制を採るなら改修は小さい:
- 今ある「対象: ⏰凸可能のみ」(`onlyAvailableNow`・1時間) を **「このブロックに出られる人」** に広げる (H と同じ動き)
- 配信は **次のブロックぶんだけ**。1日ぶんの参考案は運営が眺める用に従来どおり出せる
- 時間のアンケートはブロック 7 つのチェック (PAD でも Discord でもデータは同じ形。内部の 1 時間刻み `hXX` は残し、見せる・聞く単位だけブロックにする)
- 模擬の締め切りは「自分が凸するブロックの前まで」
- 運営の「模擬の取り込み」: Discord のスクショを落として読み取り → 誰の模擬かを選んで登録 (今の `_FILE_DROPS` + OCR の経路を運営画面から他人の模擬として入れられるようにする)

## 5. モック (5枚・場面は「ハード日 18:10・夕方のブロックを組むところ」)

メンバー (スマホ・下メニューは ホーム / 時間 / きょうの凸 の 3 つだけ)
1. ホーム — 7 ブロックの帯 (済んだ / いま / 未定)、「このブロックのあなたの凸」と ✅ 確認しました、次のブロックは「まだ決まっていません・20:30 ごろ配信」、運営が登録した自分の模擬
2. 出られる時間 (前日) — 7 ブロックのチェック。「昼までに Lv1 踏破が目安」「夕方 · Lv3 が開く目安」の添え書き
3. きょうの凸 — ブロックごとに 1 行。済んだ凸は ✓ と実績、いまのブロックは枠、先のブロックは「未定」

運営 (PC)
4. ブロック盤 — 条件は「このブロックに出られる N 人 / 全員 (参考案)」と「置いた駒を動かさない / 全部任せる」の 2 つだけ。ボス 5 行 × ブロック内の時刻 3 列に駒を置く。各ボスに「置いた凸の合計 → 踏破見込み ✅ / あと 34B (夜へ)」。右に「まだ置いていない人」のピースと「夜に回す人」。配信は「夕方のぶんを配信 (14凸)」
5. 模擬の取り込み — スクショを落とす → 読み取り → 誰の模擬か (投稿者から推定)・属性・ダメージ・編成を確認して登録。キャラ被りの警告。「届いていない人」とその期限 (= 自分のブロックの前)

モックで仮に置いた未決: 模擬タブ・予約の申請・凸報告はメンバー画面から外した (本人が報告する案ならホームのカードにボタンが 1 つ増えるだけ)。時間のアンケートは PAD 側で描いた (Discord なら 2 枚目は要らず、運営が入れる画面になる)。

## 7. ふるりの判断 (2026-10-17・Claude との会話で)

1. **ブロックの区切りはそのときのユニオンメンバー次第** → 固定にしない。シーズンごとに運営が数と境界を決められる設定にする (既定は 7 ブロック)。
   内部の 1 時間刻み `hXX` はそのまま。ソルバー・時間割・ベンチは区切りを変えても動く
2. **時間のアンケートは PAD で持つ** → 今の「戦闘可能時間」を残し、見せる・聞く単位だけブロックのチェックにする (モック 2 枚目)
3. **模擬の提出シートはメンバー画面から消す。ただし「必要になったら戻すのが容易」であること** → 削除ではなく **運営の設定で隠す** (「メンバーの模擬提出」ON/OFF)。
   データの形 (`player_damages`) は変えない。編成編集モーダルと OCR は運営が他人の模擬を登録する経路で使い続けるので腐らない。
   戻すときは本人だけの部分 (提出ボタンの本人判定・予約済みの印) を練習モードで一周する。練習の「メンバー編」の課題はスイッチに合わせて切り替える
4. **凸報告は本人がする → 運営がチェック** → ホームの凸報告ボタンは残す。運営側に「きょうの凸報告」の確認欄 (プランとの食い違いに印・✓ 確認) を足し、
   最後は BlaBlaLINK の一括読み取りと突き合わせる (第45回は報告漏れ 5 凸・申告ミス 1 件があった)

ねむねこさんへの確認は上の 6 のまま (区切りの目安を置くかは、区切りが可変になるので「シーズン設定の添え書き」として扱う)。
