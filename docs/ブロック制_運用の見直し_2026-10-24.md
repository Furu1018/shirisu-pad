# ブロック制の運用の見直し: 前日の入力を運営チームに寄せる (2026-10-24・すり合わせ中)

ふるりの構想 (2026-10-24 朝) を文章にしたもの。**まだ決定ではない** — ふるりと Claude の理解のずれを無くしてから改修に入る。
決まったことには「✅ 決定」を付けて残す。§1 と §2 はそのまま**メンバー向け / 運営向けの説明文**として使える書き方にしてある (言葉は `docs/用語集.md`)。

> 構想の要点: **メンバーは前日に Discord へ報告するだけ、しりすこPAD に入力しない**。参加可能時間・模擬・凸先の希望は運営チームが PAD に登録する。
> 当日は運営からの連絡 (配信) を待ち、凸したら Discord に結果を貼る。運営はブロックの頭ごとに HP を照合し、結果を取り込み、次のブロックを組んで配信する。

## 1. メンバーがやること (メンバー向けの説明文の下書き)

### 前日まで — 模擬ができるようになったら、Discord に 3 つ

1. **参加可能時間と凸数** — 出られるブロックと、そのブロックで何凸するか。例「朝 1・夜 2」「夕方だけ 3」。
   ブロックは 朝 5〜8時 / 午前 9〜11時 / 昼 12〜14時 / 午後 15〜17時 / 夕方 18〜20時 / 夜 21〜23時 / 深夜 翌0〜4時。
   出られない回は「今回は難しい」と伝える。凸数を決めていなければブロックだけでよい (運営におまかせ)
2. **模擬のスクショ** — 属性ごと (5 属性)。18 時以降に出られる人は、ボス 5 の属性だけ**編成を 2 つ** (Lv4 のボス 5 は HP 無限で、2 編成目がそのまま与ダメになる)
3. **凸先の希望があれば** — 「夕方に 風圧PT の編成① で行きたい」のように (これが「予約」)。無ければ運営が組む

運営が PAD に登録すると、ホームの **⏰ 参加可能時間** と **📘 登録された模擬** に出る。違っていたら Discord で運営へ (PAD で直す操作は無い)。

### 当日 — 運営からの連絡を待つだけ

- 自分のブロックの前に**配信の通知**が来る → ホームの **📅 きょうの凸** で「いつ・どのボス・どの PT の どの編成」を見て **✅ 確認しました** を押す
- 時刻になったら凸 → **結果の画面のスクショを Discord へ**。運営が登録すると きょうの凸 に ✓ が付く
- 前のブロックの結果で予定が変わることがある。**新しい配信の通知が来たら、もう一度 きょうの凸 を見て ✅**

### しりすこPAD で触るのは

名乗り (最初の 1 回) ・ 通知を ON にする ・ 配信を見る ・ ✅ 確認しました。**入力は無い**。

## 2. 運営チームがやること (運営向けの説明文の下書き)

### 前日より前

- 👑 シーズンを作る (ボス・属性・HP・ハード日)。ブロックの区切りは既定の 7 つ (変えるなら ✏️ シーズン編集)
- 🔔 通知の疎通確認を送る (レイドの 2 日前から)

### 前日 — Discord の報告が来たら、人ごとに PAD へ

1. **⏰ 参加可能時間と凸数を登録** (新) — 👥 メンバーの行から。前回の登録が既定で入っているので、変わった所だけ直す。「今回は難しい」もここ。報告の無い人には催促
2. **📸 模擬を登録** — スクショを取り込む (いまの機能)。**取り込みの画面で「この編成で予約する」→ ブロックを選べる** (新)。あとから 🧱 組む の予約カードからも登録できる (新)
3. **🧱 朝のブロックを組む** → 盤で確かめる → 必要なら手で直す → 📤 配信 (通知は自動)。模擬が出そろっていれば「残りのブロックを一気に組む」で 1 日ぶんの予想を先に出せる

### 当日 — ブロックの頭ごと (🧱 組む の手順の帯のとおり)

1. **⚔️ HP を照合** — BlaBlaLINK のボス一覧のスクショ → 5 体まとめて読み取り → 差分を見て保存 (楽にする・新)
2. **📥 結果を取り込む** — Discord に貼られた凸のスクショを登録 (✓ が付く)。報告の無い凸は「聞く」か「凸していない」に
3. **🧱 次のブロックを組む** (自動) → 盤で手で直す (置けないマスは理由が出る・新) → 📤 配信
4. 必要なら 🏁 締め凸検索 → Discord で声かけ → 盤に置く

## 4. 改修の段階 (案・決まってから着手)

- **9a 運営が参加可能時間と凸数を登録** — 👥 メンバーの行に「⏰ 時間を登録」。本人の時間シートと**同じ部品** (ブロックのチップ + 凸数 + 今回は難しい) を「誰のか (forPlayer)」付きで出し、`supabaseSaveAvailability` + `supabaseConfirmAvailability` を本人の代わりに書く (今期の確認も運営が付ける・活動ログに「運営が代理で登録」)。前回の登録を既定に。
  メンバー側: lite では時間シートの編集を隠し、ホームの ⏰ 帯は読み取り専用 + 「直したいときは Discord で運営へ」。催促 (📣) の文面も「Discord で教えてください」に
- **9b 運営発の予約** — 📸 取り込みのプレビューに「この編成で予約する → ブロック」。あとからは 🧱 組む の予約カードの「＋ 予約を登録」(誰が・どの編成・どのブロック)。
  作り方は **📌 仮置き (ブロック) を置いて即 🔒 確定** の 2 遷移を 1 操作に (既存の遷移表のまま = **SQL の変更は要らない見込み**・実装時に確かめる)。理由は `ops_registered`。承認待ちの状態は使わなくなる
- **9c メンバー画面から入力の入口を外す** — 「枠を予約する」・時間シートの編集・今期の確認ボタン・ヒーローの「⏰ 出られる時間を確認する」を lite で隠す (CSS・コードは残す)。ヒーローは「前日の報告は Discord で」
- **9d 置けない理由をその場で** — 盤の沈んだマスを押したら「置けません: 属性が合わない / その時間は出られない / 凸数の上限 / 済んだ凸」などを出す (`planBoardDomain.canPlace` / `reservationsDomain.canPin` の label を使う・判定は増やさない)。🧩 ピース箱の各ピースに「置ける場所が無い理由」
- **9e ボス HP の照合を楽に** — ⚔️ HP: スクショを選ぶ / 落とす / 貼る (PC) → 5 体の読み取り → **いまの値との差分だけ**を見せる → 1 タップで保存。読み取れなかった体だけ手で。手順の帯の「30 分以内」はそのまま
- **9f 練習モードの作り直し (運営編)** — 前日 = Discord の報告を登録 (時間 + 凸数 → 模擬 + 予約) → 朝を組む → 手で 1 つ直す → 配信 / 当日 = HP を照合 → 結果を取り込む → 次を組む → 配信。メンバー編 = 配信を見る → ✅ → 凸して Discord (入力の課題は無くす)
- **9g 文章の説明** — この §1・§2 を Discord 用に整えて配る (画像 `docs/使い方の説明_2026-10-23/` は流れが変わるので作り直し)

順番の案: 9a → 9b → 9c (ここまでで前日の流れが新しくなる) → 9d → 9e → 9f → 9g。9a〜9c は 1 日、9d〜9f は 1〜2 日の見込み。

| Q1 | メンバーの PAD での入力は**ゼロ**にするか (時間シート・予約の入口を隠す)。それとも「本人も入れられる・運営も代わりに入れられる」の両立か | **ゼロ** (構想どおり)。両立にすると「どちらが正か」でまた迷う。従来の画面は member_input=full で戻せる |

| Q3 | Discord の時間の報告はどんな形にするか | 「朝 1・夜 2」のように**ブロック名 + 凸数**。凸数が無ければブロックだけ。「今回は難しい」も一言。運営の入力は前回の登録が既定で入るので差分だけ |
| Q4 | 運営が予約を登録したとき、本人に通知するか | **通知する**「あなたの予約を登録しました (夕方・風圧PT 編成①)」(いまの承認の通知と同じ)。本人が自分の希望が入ったと分かる |
