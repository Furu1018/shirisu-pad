# SLv補正テーブル (slv-ratio.json) の内部法則

2026-08-23 の SLv1183 拡張作業で、テーブル全域 (1〜1183) を数値解析して見つけた規則の記録。
新旧データ (1〜1000 / 1001〜1183) は**完全に同一の法則の続き**だった。

## 法則 (SLv21以降を2ルールで説明できる)

1. **20レベルブロック + 境界で約 +5% ジャンプ**
   SLv x0 → x1 (例: 1000→1001) の境目で直前値の **約 +5%** が乗る。
   厳密な5.00%ではなく (テーブルが整数のため)、表示上は序盤 4.82% から始まり
   SLv200 以降は 4.99〜5.00% に収束する。
   **例外: SLv10→11** は +68 (+6.53%) で、この規則に乗らない唯一の境界
   (序盤だけ 1〜10 / 11〜20 の10レベルブロックになっている)。

2. **ブロック内はほぼ一定の足し算。増分は40レベル帯ごとに1段階アップ**
   1レベルあたりの伸びは基本単位 **約33.667** (= (r(20)−r(11))/9) の整数倍で、
   倍率は **SLv 1〜40 が ×1、41〜80 が ×2、81〜120 が ×3、…** と
   40レベル帯ごとに1ずつ増える (倍率 = ceil(SLv/40))。
   整数丸めのため隣接差分は±1揺れる (例: 961〜1000 は 842 と 843 が混在) —
   下表の増分は**ブロック内平均**。

   | SLv帯 | 増分/Lv |
   |---|---|
   | 961〜1000 | 単位×25 (≈843) |
   | 1001〜1040 | 単位×26 (≈876) |
   | 1041〜1080 | 単位×27 (≈910) |
   | 1081〜1120 | 単位×28 (≈944) |
   | 1121〜1160 | 単位×29 (≈978) |
   | 1161〜1183 | 単位×30 (≈1011) |

   全ブロックで式とのズレは約 0.0005〜0.045 単位 (整数丸めの範囲内)。
   継ぎ目の 1000→1001 にも特別な段差はない。

- 相対成長は漸減する: 100Lv上げの倍率は SLv100→200 で 3.34倍、SLv1083→1183 で 1.35倍。
  5%ジャンプの複利が支配的になり、100Lvあたり約1.28倍 (=1.05⁵) に漸近する。

## 何に使うか

- **次回拡張 (SLv1184〜) の取り込み検証**: 「既存範囲と全件一致」に加えて
  「新規範囲がこの式 (約+5%境界 / 単位×n の線形区間) から外れていないか」をチェックできる。
  外れていたら実測ミス・写し間違い・ゲーム側の仕様変更のいずれかを疑う。
- 解析の再現 (21起点・20間隔で各ブロックのジャンプ%と平均増分を列挙。SLv10→11 の例外は対象外):

  ```sh
  node -e '
  const d=JSON.parse(require("fs").readFileSync("data/slv-ratio.json","utf8")).data;
  const r=s=>d[String(s)], unit=(r(20)-r(11))/9;
  for(let st=21;st<=Object.keys(d).length-2;st+=20){
    const end=Math.min(st+19,Object.keys(d).length);
    console.log(st, "jump%", ((r(st)-r(st-1))/r(st-1)*100).toFixed(2),
      "step/unit", ((r(end)-r(st+1))/(end-st-1)/unit).toFixed(2));
  }'
  ```

## 注意

- これは**観察された規則**であり、ゲーム側が保証している式ではない。将来のバランス調整で
  崩れる可能性はある — 崩れたときは「データが間違い」と決めつけず本文の値を優先し、
  このメモを更新すること。
- 正データはあくまで `data/slv-ratio.json` (めいでん実測)。この式から値を生成して
  テーブルを埋めることは**しない** (実測範囲外を受け付けない方針は GB 側 CHECK 制約と同じ)。
